## 2026-08-31 - Optimize MultiheadAttention weights
**Learning:** PyTorch nn.MultiheadAttention returns attention weights which can be unnecessary overhead when only the attended output is needed. Skipping attention weights calculation by using `need_weights=False` and unpacking to `_` optimization avoids unnecessary calculation and memory allocation. Memory context indicates some tests inherently fail due to num_classes logic, which is acceptable since it existed prior to this change.
**Action:** When using `nn.MultiheadAttention` in this codebase where the second return value (attention weights) is unused, explicitly set `need_weights=False` and explicitly unpack it as `_` to optimize performance.
## 2026-08-31 - Key Error in API Tests (mag_baro)
**Learning:** The `MultimodalGaitNet` forward pass extracts `mag_baro` features from the input batch (`batch['mag_baro']`). However, the API's `_sensor_to_tensors` function in `api/service.py` does not include `mag_baro` in the dictionary it creates from the `SensorData` schema (which also lacks it). This raises a `KeyError: 'mag_baro'` during API tests.
**Action:** When extracting `mag_baro` features in `_sensor_to_tensors` (e.g. `api/service.py`), provide a dummy tensor of zeros to satisfy the model requirement since it's missing in the `SensorData` schema, or update `api/service.py` to construct a dummy tensor matching the expected shape `(1, mag_baro_channels, seq_len)` if `mag_baro` is not provided.
## 2026-08-31 - IndexError in reasoning engine explain method
**Learning:** Some test cases run with randomly initialized models or unexpected config mappings which causes the predicted class index to exceed the predefined number of labels in `self.CLASS_NAMES_KR`. The reasoning engine's `explain` method accesses `self.CLASS_NAMES_KR[pred]` which throws an `IndexError`. Memory context explicitly warned about this.
**Action:** When accessing class names from lists or arrays using a prediction index (e.g. `self.CLASS_NAMES_KR[pred]`), use safe index checking or a fallback mechanism to prevent `IndexError`. For lists, check if `pred < len(self.CLASS_NAMES_KR)` before accessing.
## 2026-08-31 - Fix AssertionError in TestClassify and TestReasoning API tests
**Learning:** API Tests assume that prediction classes are contained within a strict predefined set `{'normal', 'antalgic', 'ataxic', 'parkinsonian'}`, which is only 4 classes. However, the model actually maps dynamically based on `GAIT_CLASS_NAMES` using an index that can exceed 4 (up to `num_classes` which is 11). Thus, predictions fall back to `unknown_X`, breaking the strict set assertions and exact dict key assertions.
