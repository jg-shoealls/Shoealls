## 2024-07-07 - Python environment path vs pytest isolation
**Learning:** `pytest` executed with `PYTHONPATH=src` using the system Python failed with `ModuleNotFoundError` for dependencies like `numpy` and `torch`, despite the dependencies being installed in the `.pyenv` Python environment. `python -m pytest` correctly uses the `.pyenv` environment. When testing components relying on `configs/default.yaml` (e.g. `test_reasoning.py`), modifying the `config` object in test fixtures (e.g. `config["data"]["num_classes"] = 4`) avoids `KeyError` and `IndexError` index out of range errors due to default configs mapping to 11 classes instead of 4.
**Action:** Use `python -m pytest` instead of just `pytest` when multiple Python environments exist to ensure modules installed via `python -m pip` are correctly found. Continue overriding config dummy models to match expected class counts in test fixtures.
