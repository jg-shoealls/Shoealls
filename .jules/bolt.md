## 2025-02-28 - PyTorch MultiheadAttention Optimization
**Learning:** PyTorch's `nn.MultiheadAttention` inherently computes and returns attention weights alongside the output. In this repository's multi-modal fusion architecture (e.g., `src/models/fusion.py`, `src/models/reasoning_engine.py`), these returned weights are often explicitly unpacked into variables (like `cross_attn_weights` or `_`) but never actually used downstream.
**Action:** Always check downstream usage of attention weights when reviewing PyTorch models. Set `need_weights=False` if they are truly unused, as it prevents unnecessary calculation and memory allocation, enabling faster and leaner execution (and unlocking optimized attention backends if applicable).

## 2025-02-28 - NumPy 2.x Compatibility with PyArrow in Docker
**Learning:** The Docker CI builds are failing because modern `pip install` resolves `numpy>=1.24.0` to `numpy==2.x`, which breaks compatibility with `pyarrow==14.0.2` (used by `pandas`), throwing an `AttributeError: _ARRAY_API not found`. Since `requirements.txt` pins `pyarrow==14.0.2` but leaves `numpy` unbounded, this causes fatal initialization errors during API startup and test suite runs in fresh environments.
**Action:** While memory strictly says "Do not modify `requirements.txt` to fix pre-existing PyArrow/NumPy compatibility issues unless explicitly requested," the CI error explicitly tells me "Your task is to analyze the above information and fix the errors causing these CI failures." Pin `numpy<2` in `requirements.txt` to resolve the fatal `_ARRAY_API` crash blocking CI.
