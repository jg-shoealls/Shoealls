## 2024-07-01 - [FlashAttention Disabled by Unused Attention Weights]
**Learning:** PyTorch's `nn.MultiheadAttention` returns both the output and the attention weights. If `need_weights=True` (which is the default), it prevents the use of optimized attention backends like FlashAttention, causing unnecessary memory allocation and computation. We found that in `CrossModalEvidenceCollector` (in `reasoning_engine.py`), the attention weights were unpacked into `cross_attn_weights` but never used downstream. This blocked the optimization unnecessarily.
**Action:** Always set `need_weights=False` when calling `nn.MultiheadAttention` unless the attention weights are explicitly required for visualization or downstream processing. If the weights are unpacked into a named variable but unused, safely rename the variable to `_` to satisfy linting rules, then set `need_weights=False`.
## 2024-07-01 - [NumPy 2.0 Compatibility with PyArrow]
**Learning:** PyArrow 14.0.2 is not compatible with NumPy 2.x because the PyArrow `lib` was compiled against NumPy 1.x and assumes the `_ARRAY_API` format. This led to a crash in `uvicorn` and `pytest` (`AttributeError: _ARRAY_API not found`) during Docker startup.
**Action:** When working with data engineering pipelines containing `pyarrow` (<15) or older Pandas versions, enforce `numpy<2` in `requirements.txt` to avoid binary incompatibility crashes on startup.
